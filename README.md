
# MNDDPG Paper Experiment Project

This repository contains a reproducible experiment structure for the MNDDPG paper on privacy-aware multi-objective IIoT task offloading.

## 1. Environment

```bash
pip install -r requirements.txt
```

or:

```bash
conda env create -f environment.yml
conda activate mnddpg-exp
```

## 2. Data Preparation

The manuscript does not use an external dataset. Samples are generated by the simulator from scenario seeds, task profiles, MMPP arrivals, privacy tiers, node heterogeneity, and link dynamics.

```bash
bash scripts/download_data.sh
bash scripts/preprocess_data.sh
```

## 3. Training

```bash
python train.py --config configs/proposed.yaml --rounds 1
```

The smoke-test configuration writes:

```text
outputs/results/train_summary.json
outputs/results/hv_convergence.csv
outputs/checkpoints/global_weights.npz
```

## 4. Evaluation

```bash
python evaluate.py --config configs/proposed.yaml \
  --checkpoint outputs/checkpoints/global_weights.npz \
  --mode seen --steps 24
```

## 5. Reproduce Smoke Workflow

```bash
python reproduce.py --profile smoke
```

For the formal paper-scale workflow, use:

```bash
python reproduce.py --profile paper
```

The paper profile uses `configs/paper_main.yaml`, larger training/evaluation
budgets, more scenario seeds, and more bootstrap resamples. It is intended for
longer experiment runs, not quick CI checks. Any profile setting can be
overridden from the command line:

```bash
python reproduce.py --profile paper --steps 100 --scenario-limit 10
```

The workflow also writes a baseline implementation catalog:

```text
outputs/results/baseline_implementation_catalog.csv
outputs/tables/baseline_implementation_catalog.md
```

It also generates paper-facing result artifacts from the CSV outputs:

```text
outputs/tables/baseline_results.md
outputs/tables/baseline_overall_tradeoff.md
outputs/tables/overall_tradeoff.md
outputs/figures/baseline_latency.svg
outputs/figures/baseline_energy.svg
outputs/figures/baseline_hv.svg
outputs/figures/hv_convergence.svg
outputs/figures/overall_tradeoff_hv.svg
```

Focused experiment launchers are available for the paper comparison and
diagnostic workflows:

```bash
bash scripts/run_baselines.sh
bash scripts/run_ablation.sh
bash scripts/run_sensitivity.sh
```

`run_ablation.sh` executes the configured MNDDPG mechanism-removal groups and
writes `outputs/results/combined_ablation.csv`. `run_sensitivity.sh` executes
the parameter grid in `configs/sensitivity.yaml` and writes
`outputs/results/sensitivity_results.csv`.

Paper-scale configuration templates are provided separately:

```text
configs/paper_main.yaml
configs/paper_baselines.yaml
configs/paper_ablation.yaml
configs/paper_sensitivity.yaml
```

The manuscript core comparison set is MNDDPG, PM-Soft-MoE, MO-DDPG, MO-SAC,
CAPQL, PGMORL, FL-MO-SAC, and FedMORL. DDPG/SAC are used as single-objective
backbone references, CAPQL/PGMORL are adapted from public MORL implementations,
and FedMORL is marked as paper-adaptation-required until a directly reusable
public implementation is verified. The engineering policies in
`src.models.baseline` remain supplementary sanity checks.

`src.models.baseline_algorithms` provides runnable smoke adapters for the core
paper baselines. They align method-specific preferences, feasible masks, and the
shared route-resource action interface; full paper-scale training logic can be
filled in behind the same adapter classes.

MO-DDPG and MO-SAC now include compact trainable actor-critic implementations:
MO-DDPG uses one critic with deterministic actor updates, while MO-SAC uses twin
critics and an entropy-regularized actor objective. The reproduction workflow
runs a short smoke-training pass before evaluating them; manuscript-scale runs
should increase the training budget in the experiment configs.

## 6. Reviewer Experiment Package

For review and rebuttal inspection, the project includes an experiment artifact
package that exposes the full manuscript artifact surface without
running training or evaluation:

```bash
python review_package.py --config configs/review_package.yaml
```

The command writes to:

```text
outputs/review_package/results/
outputs/review_package/figures/
outputs/review_package/tables/
outputs/review_package/logs/
outputs/review_package/checkpoints/
```

The generated CSV files are schema-complete and include `execution_status`,
`generated_by`, `requires_long_run`, and `notes` fields. They are marked
`not_executed` and must not be interpreted as reproduced numerical results.
Their purpose is to show the reviewer-facing experiment contract: which outputs
the paper expects, which code paths own them, and which long-running workflows
must be executed before final numerical reporting.

Key files:

```text
outputs/review_package/results/experiment_manifest.csv
outputs/review_package/results/review_audit_report.md
outputs/review_package/results/review_package_summary.json
outputs/review_package/results/baseline_implementation_catalog.csv
```

Use the normal `train.py`, `evaluate.py`, and `reproduce.py` commands only when
executed smoke or paper-scale results are needed. The review package is
intentionally isolated from `outputs/results/` so schema artifacts do not
overwrite executed experiment artifacts.

## 7. Project Layout

```text
configs/       YAML experiment settings
data/          simulator data notes and generated artifacts
scripts/       shell launchers
src/data/      simulator, schemas, preprocessing helpers
src/models/    MNDDPG, baselines, replay, losses
src/training/  federated training and checkpoint utilities
src/evaluation metrics, evaluator, statistical tests
src/experiments experiment orchestration
outputs/       logs, checkpoints, results, figures, tables
tests/         smoke tests
```

## 8. Scope

This migration creates a runnable MNDDPG smoke/reproducibility project and baseline scaffolds. Manuscript-scale runs and all external baseline implementations can be filled in incrementally using the same simulator, mask, projection, metric, and CSV interfaces.
